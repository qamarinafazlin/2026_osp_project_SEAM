Understanding Flask: How Routes, Sessions, and Jinja2 Templates Work Together in EwhaMarketContextWhile building the EwhaMarket web application in 2026_osp_project_SEAM, I used Flask (app.py) together with HTML templates (templates/) to handle navigation, product and review pages, form submissions, and user login state. Because HTTP requests are stateless by default, I wanted a clear understanding of how Flask connects URLs to Python functions, passes context into templates, and remembers who is logged in across pages.   Problem or GoalWhen a web app has separate pages for viewing products (/list), opening product details (/view_detail/<name>), logging in (/login), and liking items (/toggle_like/<name>), it is easy to lose track of how data moves between the server and the browser. The goal of this post is to explain three core Flask concepts—routing (including dynamic URLs), template rendering with Jinja2, and user sessions (session)—using real examples from app.py and our templates.
